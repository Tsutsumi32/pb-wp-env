# Design brand（案件共通）

下層ページ実装（`@subpage-design-implement`）で参照するブランドドキュメント。

**優先**: 本ファイルの **その他特記事項（手動）** および記載済みの方針が最優先。画面固有は各 `brief.md`。矛盾時は特記事項 → 表現の方針 → brief 仕様メモ。

## メタ（生成済み判定）

ファイルはテンプレとして最初から存在する。**表現の方針を実装から調査・記入したか**は次で判定する。

- Expression-status: pending
- Updated: YYYY-MM-DD
- Sources: （生成時に記入。例: front-page、about、主な SCSS / modules パス）

| Expression-status | 意味 |
|-------------------|------|
| `pending` | 未生成（テンプレのまま／調査前）。`@subpage-design-implement` は **先に生成して停止・報告** |
| `ready` | 生成済み（または人手で ready にした）。以降の依頼では再生成しない（「再生成」「brand を更新」明示時のみ） |

`Expression-status` が無い・不明な旧テンプレも **pending 扱い**。

## Figma 参照（手動）

未実装の JSON `componentType: design` コンポーネントを MCP 取得するときの参照先。**人手で書く**。エージェントは生成時に触らない・消さない。

- コンポーネント一覧 URL: （空可。Figma のコンポーネント一覧フレーム等の MCP 用 URL）

## 全体の方針

実装済みの **TOP 画面**および **下層画面**のデザインを方針として参照する。  
（前提: `@subpage-design-implement` 実行時は、通常 TOP と下層 1 ページが実装済み）

エージェントは生成時に、上記 Sources の画面・コードを調査し、下の「表現の方針」へ要約を書く。値の羅列より **どう扱っているか**を短く書く。
