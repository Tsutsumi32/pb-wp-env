# Figma 実装後のブラウザ確認

方針の正本: `cursour-allways-rules.mdc`「ブラウザ確認（実装後）」。本ファイルは **手順**。

Chrome DevTools MCP は使わない。手段は **`cursor-ide-browser`**。

## いつ行うか

呼び出し元が条件を満たすときだけ実行する（満たさなければ開かない）。

| 呼び出し | コンソール | 大差検知 |
|----------|------------|----------|
| `@figma-page-implement` Phase 3（全セクション `done`） | ページ | ページ全体 1 回 |
| `@figma-coding` **直呼び**で PHP または JS を変更 | ページ | —（下の行と同時ならまとめて 1 回） |
| `@figma-coding` **直呼び**でセクションを一通り（template+style）**新規**実装 | （上に該当なら） | **当該セクション** 1 回 |
| `@figma-template-coding` / `@figma-js-coding` **直呼び**で PHP / JS を変更 | ページ | しない |
| 親が `@figma-page-implement` の途中セクション | **しない**（Phase 3 に寄せる） | **しない** |
| `@figma-style-coding` のみ・既存の微修正 | しない | しない |

ユーザーがセルフチェック不要と明示したら `Self-check: skipped — user` で完了してよい。

## 手順

1. **URL**  
   `inc/config/pages.php`（または同等）から page-slug のパスを解決する。トップ扱いのみ `/` を候補可。**不明なら確認して止める**（推測 URL 禁止）。

2. **ブラウザで開く**  
   読み込み完了まで待つ。viewport は計画または対象の主側で足りる。  
   navigate → 必要なら lock → 確認 → unlock。  
   使えない／到達できない場合: `Self-check: skipped — <理由>`（**実装完了自体は妨げない**）。ホストから Docker 内ホスト名（例: `http://php`）に届かないときは、到達可能な URL（例: `localhost` + 公開ポート）を使う。それでも不明なら止めて確認する。

3. **コンソール**（実施対象のとき）  
   error および未捕捉例外（pageerror 相当）。  
   - 実装起因で直せる → 修正して再読込  
   - 直せない／第三者起因 → 報告に残す  
   - warning は報告してよいが、それだけでは失敗にしない

4. **大差検知**（実施対象のとき）  
   対象 node の Figma `get_screenshot` と、実装の Browser スクショを **目視で一度だけ**比べる。セクション対象なら可能なら当該ブロックへスクロールする。  
   **報告する（大差）**: 空／真っ白／500、主要ブロック欠落、レイアウト方向が明らかに違う、背景が別色系統、対象の高さが Figma に対しおよそ半分未満または 2 倍超、文書が viewport を明らかに超えて横スクロール。  
   **無視する**: 数px・余白・行間、色の微差、フォントレンダリング、仮画像と Figma 写真の差、キャプチャ範囲・ヘッダー被り・スクロール位置。**迷ったら報告しない**。  
   **見た目を理由にした SCSS／PHP の自動修正は禁止**（報告のみ。人が再指摘）。スタイルが全く当たっていない場合はビルド未反映の可能性を書いて **修正しない**（ビルド実行禁止）。px 差分画像は保存しない。

5. **記録**  
   ページ実装: 計画 Progress に 1 行。部分実装: 完了報告に 1 行。  
   例: `Self-check: ok (console)` / `ok (console+visual)` / `fixed console` / `large-diff — <要点1行>` / `skipped — …`
