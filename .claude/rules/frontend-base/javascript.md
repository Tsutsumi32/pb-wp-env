# JavaScript記述ルール

JavaScript共通の記法（ES6）・動きの配慮（reduced-motion）・コメント階層・機能単位の記述順を扱う。DOM参照は `.claude/rules/project/javascript/coading.md` を参照。

JavaScriptを記述するすべてのファイルで、適切に階層づけたコメントと、機能単位で整理されたコード構成を意識する。

DOM の要素特定（`querySelector` 等）は class / id 禁止・`data-*` 必須。手順と例外は `.claude/rules/project/javascript/coading.md`「画面JS実装時の手順」「DOM参照」、属性名は同 `naming.md` を参照。

## 記法（ES6）

原則として ES6（ECMAScript 2015）以降の記法を用いる。`const` / `let`、アロー関数、分割代入、テンプレートリテラル、`class`、モジュール（`import` / `export`）、デフォルト引数・残余引数など、ビルド対象ブラウザや実行環境で問題ない範囲でモダンな構文を選ぶ。意図的にレガシー互換のみとする場合は、個別プロジェクトのルールに従う。

## 動きの配慮（prefers-reduced-motion）

アニメーション・スクロール連動・スムーススクロールなど、JavaScript で動きを付ける実装では **`prefers-reduced-motion: reduce` への対応を前提とする**。

- 装飾の動きは reduce 時に止め、最終状態（表示状態）で見せる。reduce でもコンテンツはすべて閲覧・操作できる状態にする
- **それ自体が動作しないとコンテンツが見られない・操作できないもの**（横スクロールコンテンツ、Swiper 等のカルーセルなど）は、reduce でも制限しない

分類・実装方法・確認方法は `.claude/rules/frontend-base/reduced-motion.md`、GSAP 固有は `@gsap` を参照する。

## 基本構成

ファイル内の記述順は、上から以下の流れを基本とする。

1. `import` 文など、テンプレートや環境に依存する記述
2. ファイル全体の説明コメント
3. 関連する機能単位のまとまり
4. ライフサイクル関連の処理

ライフサイクル関連の処理は、原則としてファイルの一番最後に記載する。

## コメント階層

JavaScriptでは、`_template.js` の形式に合わせて以下のコメントを使い分ける。

### ファイル説明

ファイルの役割や対象ページ、対象機能が分かる説明をファイル上部に記載する。

```js
/************************************************************
 * ファイルの説明
 ************************************************************/
```

### 機能単位の大きなまとまり

複数の機能がある場合は、関連する機能ごとにコメントで区切る。

```js
// ----------------------------------------------------------
// 関連機能1 - 複数の機能がある場合は機能毎に 定数 - 変数 - メソッド - 初期化
// ----------------------------------------------------------
```

### 機能内の小さなまとまり

機能内でさらに階層を分ける場合に使用する。

```js
/* 関連機能1 - さらに階層を作る場合
-------------------------------------------- */
```

### 処理内コメント

JSDocコメントとは別に、処理の意図が伝わりにくい箇所には処理内コメントを適宜記載する。見れば分かる処理説明や、プロパティ単位の過剰なコメントは避ける。

```js
// 処理は適宜説明コメント 簡潔に
```

## JSDocコメント

定数、変数、メソッドにはJSDocコメントを必ず記載する。JSDocだけで意図が伝わらない分岐・補足条件・例外的な処理は、処理内コメントも併用する。

```js
/** 変数・定数はJSDocコメント */
const message = '';

/** 変数・定数はJSDocコメント */
let currentIndex = 0;
```

```js
/**
 * メソッドの役割を記載
 * @param {String} text メッセージ
 * @returns {String} メッセージ
 */
const getMessage = (text) => {
  return text;
};
```

## 機能単位の記述順

JavaScriptは関連する機能ごとにまとめ、各機能内では以下の順番で記載する。

1. 定数
2. 変数
3. メソッド
4. 初期化（イベント登録・DOM 反映・状態のセットアップなど、その機能を動かすための起動処理）

関連する機能のコードをファイル全体に分散させず、上から同じ流れで読める構成にする。複数機能がある場合は、機能ごとに同じ順序を繰り返す。

```js
// ----------------------------------------------------------
// 関連機能1
// ----------------------------------------------------------
/** 関連機能1で使用する定数 */
const option = {};

/** 関連機能1で使用する変数 */
let current = null;

/**
 * 関連機能1の処理を実行
 * @returns {void}
 */
const runFeature = () => {
  // ...
};

/**
 * 関連機能1を初期化
 * @returns {void}
 */
const initFeature = () => {
  // イベント登録など
};

// ----------------------------------------------------------
// ライフサイクル
// ----------------------------------------------------------
// ライフサイクルは最後に記載
```
