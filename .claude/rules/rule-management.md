# ルールファイル管理ルール

このファイルは、`.claude/rules/`・`.claude/skills/` 配下のルール・スキルファイルを作成・更新する際のルールを記載します。

## 基本原則

### 1. 2重管理の禁止
- 同じ情報を、`.claude/rules/`・`.claude/skills/` 内の複数ファイルに記載しないこと
- ルールの一元管理を徹底し、参照関係を明確にすること
- 既存のルールファイルとの重複を避けること

### 2. 関連ルールの統合
- 新規ルールを追加する際は、既存の関連ルールファイルに追記すること
- 同じカテゴリのルールは一つのファイルにまとめること
- 必要に応じて既存のルールファイルを分割・統合すること

### 3. ファイルの役割を明確化
- それぞれのルールファイルには的確な役割を設ける
- 他のファイルが担う役割のルールを記載せず、適切なファイルに記載すること

### 4. 重複内容の排除
- 重複した内容は記載しないこと
- 既存の内容と重複がないか必ず確認すること

### 5. 構成の明確化
- ルールファイルの中身の構成を最初に明記すること
- 何のためのルールなのか、どのような構成になっているのかを明確にする

### 6. 例文の適切な提示
- ルールの各項目について、必要に応じて例文を記載すること
- ルールが冗長になり複雑になるような例は避けること

### 7. 複雑化・冗長化の回避
- 1つのルールに対して冗長的に長いルールを記載しないこと
- 多くの例文を記載して複雑化しないこと

### 8. 再利用性の確保
- WordPressプロジェクト間で使い回すルールには、特定プロジェクト名、テーマ名、サイト名、固定のローカルパスなどを記載しないこと
- テーマパスやWordPressルートは `<theme-name>`、`<theme-root>`、`<wordpress-root>` などの汎用表現で記載すること
- プロジェクト固有の事情を記載する必要がある場合は、共通ルールではなく個別プロジェクト用のルールファイルに分離すること

## ツールツリーの独立管理

Cursor 用と Claude Code 用のルール／スキルは **同期しない**。各ツールは自ツリーだけを管理する。

- Claude Code エージェント: `.claude/rules/`・`.claude/skills/` および入口 `CLAUDE.md` のみ作成・更新・削除する
- Cursor エージェント: `.cursor/rules/`・`.cursor/skills/` のみ
- もう片方のツリーは編集しない。ただし `.claude/` 側に未移行のルール・スキル（Figma 実装パイプライン等）は、スキルの指示に従って `.cursor/rules/` / `.cursor/skills/` を **読むだけ**なら対象外の制約を受けない（各スキルの「関連」節に明記する）
- 共有パス（`.cursor/tmp/`・`.cursor/figma-tokens/`・`.cursor/design/`）は Cursor 側の管理のまま共通で参照してよい
- 画面キャプチャ（`_docs/capture/`）・原稿/画像シート（`_docs/sheets/`）は両ツール共通の出力先。どちらのツリーにも属さない
- 「ルールを直して」「スキルを追加して」も、明示が無い限り **Claude Code 側だけ**を対象とする
- Cursor 側との相互反映の合図（報告のみ・相手ツリーは触らない）は `@management-rule`「他ツール側への反映報告」に従う

## チェックリスト

### 新規ルールファイル作成時
- [ ] 既存のルールファイルとの重複がないか確認
- [ ] 適切なカテゴリに分類されているか確認（`frontend-base/` / `project/css/` / `project/javascript/`）
- [ ] `CLAUDE.md`「ルール参照マップ」に追加するか検討
- [ ] 他のルールファイルからの参照が必要か検討
- [ ] 再利用前提のルールにプロジェクト固有名や固定パスが含まれていないか確認
- [ ] `.claude/` 側のみを対象にしているか確認（`.cursor/` 側は編集しない）

### 新規スキル作成時
- [ ] 既存スキルとの重複がないか確認（近い役割のスキルがあれば統合を検討）
- [ ] `.claude/skills/<skill-name>/SKILL.md` に配置し、frontmatter は原則 `name` と `description` のみ
- [ ] **Cursor に載せたくない／同名衝突を避けたい**ときだけ `user-invocable: false`（`/` 非表示）と、必要なら `disable-model-invocation: true`（モデル自動起動オフ）を付けてよい（例: 本スキル `management-rule`）
- [ ] 依頼文の具体的なトリガー語を `description` に含める（Claude が自動判断で読み込むため）
- [ ] `.claude/rules/` に対応ルールがあれば参照し、長文を複写しない
- [ ] `.claude/` 側に対応ルール・スキルが無い話題（Figma 実装・トークン同期・ページ情報管理等）は、`.cursor/rules/` / `.cursor/skills/` を直接参照する旨を明記し「未移行」と注記する
- [ ] `CLAUDE.md`「ワークフロー別スキル」に一覧を追加するか検討

### 既存ルールファイル更新時
- [ ] 既存の関連ルールファイルに追記できるか検討
- [ ] 新規ファイル作成の必要性を検討
- [ ] 参照関係の整合性を確認
- [ ] `CLAUDE.md` の更新が必要か確認
- [ ] 共通ルールと個別プロジェクト固有ルールが混在していないか確認
- [ ] `.claude/` 側のみを対象にしているか確認（`.cursor/` 側は編集しない）
- [ ] Cursor 側にも反映が必要なら、完了報告末尾に「Cursor 側への反映が必要」を書いたか（`@management-rule`「他ツール側への反映報告」）
